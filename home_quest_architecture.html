A visual, interactive breakdown of the Architectural Visualization & Vastu Analysis Platform — how every piece connects, how data flows, and what technologies power it.

Giant Architecture Overview

Click any module to see what it does, which files live inside it, and how it connects to other parts. The app is built in stacked layers — each layer only talks to the one directly below it.

LAYER 1 — What the User Does
🖱️
Mouse & Touch Input
click · drag · scroll · pinch
Draw walls by clicking, move furniture by dragging, zoom in/out by scrolling
⌨️
Keyboard Shortcuts
Ctrl+Z · Escape · WASD
Undo/redo, cancel drawing, walk around in 3D first-person view
📋
UI Panels & Controls
Toolbar · Property Panel · Menus
Tool selection, wall thickness sliders, room type dropdowns, Vastu toggle
LAYER 2 — Smart Helpers (React Hooks)
✏️
Drawing Engine
useWallDrawing.ts
Step-by-step wall drawing: click to start → preview line follows mouse → click to finish. Supports chain-drawing for continuous walls.
🧲
Snap System
useSnapping.ts
Automatically aligns your cursor to the grid or nearest wall corner, so walls connect perfectly without gaps.
🎯
Selection
EditorCanvas.tsx · hit-testing
Click to select a wall, room, or furniture piece. Hit-testing lives in the canvas; the selected id is stored and highlighted.
🔍
Pan & Zoom
usePan.ts
Scroll to zoom in/out, middle-click and drag to move around the canvas. Keeps everything smooth at 60fps.
LAYER 3 — Central Brain (Zustand Store)
📐
Editor Data
editorSlice.ts
All walls, rooms, furniture positions, and snap settings. The "single source of truth" for the floor plan.
🎥
Viewer Settings
viewerSlice.ts
Camera mode (orbit vs first-person), render quality, wireframe toggle, 3D display options.
🧭
Vastu Results
vastuSlice.ts
Cached Vastu scores, which zone each room is in, compliance recommendations. Updates when rooms change.
⏪
Undo / Redo History
historySlice.ts
Snapshots the floor-plan before each action so you can undo with Ctrl+Z. Stores up to 100 steps.
LAYER 4 — Visual Output (What You See)
🗺️
2D Floor Plan Editor
SVG Canvas · 6 layers stacked
Grid dots → room fills → wall lines → furniture icons → selection highlights → drawing preview. All composited in a zoomable SVG.
🏠
3D House Viewer
React Three Fiber · Three.js
Walls become extruded 3D solids, rooms get floors, furniture becomes procedural boxes. Walk through in first-person or orbit around.
🔮
Vastu Overlays
SVG arcs (2D) · Mesh triangles (3D)
Colored pie-slices showing North/South/East/West zones. Shows where kitchens, bedrooms, puja rooms should go.
📊
Score Dashboard
VastuPanel.tsx · VastuLegend.tsx
Shows an overall Vastu score (0-100), per-room scores, and specific recommendations like "Move kitchen to SE corner."
LAYER 5 — Math & Logic Engine (Pure Functions)
📏
Geometry Math
geometry.ts · wallOps.ts
Screen pixels → world coordinates, wall thickness quads, point-in-polygon tests, line intersections.
🔍
Room Detection
roomDetection.ts
Automatically finds enclosed rooms by tracing wall loops. Uses a "follow the left wall" algorithm from computational geometry.
🧱
Wall Extrusion
extrusion.ts · transform.ts
Converts flat 2D walls (cm) into 3D box geometry (meters). Handles wall direction, thickness, and height.
🧮
Vastu Analysis
brahmasthan.ts · zones.ts · scoring.ts
Calculates the center point (Brahmasthan), lays a 3×3 grid (8 directions + center) over the plan's bounding box, and scores each room's placement against Vastu rules.
💥
Collision Detection
collision.ts
Prevents furniture from overlapping. Uses fast grid-based filtering, then precise rotated-box intersection tests.
LAYER 6 — Assets & 3D Models
🪑
Furniture Renderer
Procedural boxes · useAssetLoader.ts
Furniture is drawn as procedural boxes sized to real-world cm and colored per type, from a catalog. (Intended GLTF/GLB assets were never shipped, so boxes stand in — swappable later.)
🎨
Material System
materials.ts · shared cache
Wall/floor materials with roughness & metalness. The brick wall texture + bump map are generated procedurally on a canvas. Materials are cached and shared to save GPU memory.
🖼️
Procedural Textures
CanvasTexture (runtime)
Brick color + bump maps are painted onto an in-memory canvas at runtime (no image files, no Draco/KTX2). Generated once and reused via the material cache.
LAYER 7 — Infrastructure & Deployment
🛡️
Error Boundaries
ErrorBoundary.tsx · fallbacks/
If the 3D viewer crashes, only that panel shows an error — the 2D editor keeps working. Layered error handling.
💾
Save & Load
IndexedDB · zustand persist
Your floor plan auto-saves to the browser. Reload the page and your work is still there.
📡
Error Tracking
monitoring.ts (console shim)
A dependency-free monitoring shim: logs errors + performance marks to the console in dev, no-ops in production. Ready to swap in Sentry later without changing call sites.
🚀
Deployment
Vite build · code splitting
Production build via tsc -b && vite build, with lazy-loaded domains so 3D code is split from the UI. (Hosting/CDN is not wired up yet; repo lives on GitLab.)

Three Coordinate Spaces

Data transforms between three different measurement systems as it flows through the app.

🖥️
Screen Space
Origin: Top-left corner of the browser
Units: Pixels
Y-axis: Points downward ↓
Used by: Mouse events, DOM positioning
📐
2D World Space
Origin: Center of the canvas
Units: Centimeters
Y-axis: Points upward ↑
Used by: Floor plan model, Vastu
🏠
3D World Space
Origin: Ground center
Units: Meters (cm ÷ 100)
Y-axis: Points upward ↑ (height)
Used by: Three.js 3D scene

Technology Stack

Every technology used in the project, organized by what role it plays. Hover or click to learn why each one was chosen.

🎯 Core Framework

⚛️
React
v19.2
The UI framework. Builds the editor panels, toolbar, and overlays as composable components. Each SVG layer is a React component that re-renders independently.
UI components SVG layers hooks
🔷
TypeScript
v6.0
Adds type safety to all geometry calculations, store shapes, and component props. Catches bugs like passing pixels where centimeters are expected.
type safety interfaces Point2D / Point3D
⚡
Vite
v8.0
Build tool and dev server. Instant hot-reload during development. Splits the production bundle into separate chunks (React, Three.js, UI) for faster loading.
dev server code splitting path alias @/

🎮 3D Rendering Engine

🔺
Three.js
v0.184
The 3D rendering engine. Creates wall geometry, floor planes, handles lighting, shadows, and camera systems. Runs on WebGL in the browser.
BufferGeometry shadows materials cameras
🎨
React Three Fiber
v9.6
Makes Three.js work like React — write 3D scenes as JSX components instead of imperative code. Handles cleanup, updates, and the render loop automatically.
declarative 3D Canvas useFrame
🧰
Drei
v10.7
Helper library for R3F. Provides OrbitControls (rotate camera), Environment (lighting), Preload (warm up assets), and an FPS Stats overlay.
OrbitControls Environment Preload Stats

📦 State Management

🐻
Zustand
v5.0
Lightweight state management. Stores all floor plan data. Uses "slices" pattern to separate editor, viewer, and Vastu data. Selectors prevent unnecessary re-renders.
slices pattern selectors devtools persist
✍️
Immer
v11.1
Lets you write store updates that look like you're directly changing data (e.g., state.walls[id] = newWall), but actually creates clean immutable copies underneath.
immutable updates draft state Zustand middleware

✏️ 2D Editor

◼️
SVG (Built-in)
Browser native
The 2D floor plan is rendered as SVG, not Canvas. SVG gives per-element click events, scales perfectly at any zoom, and works naturally with React's component model.
per-element events resolution-free pattern fills

🧭 Vastu Analysis

🕉️
Vastu Engine
Custom pure math
No library needed — pure TypeScript math. Calculates the Brahmasthan (center), lays a 3×3 grid (8 directions + center) over the plan's bounding box, and scores each room (0-100) against traditional Vastu Shastra rules.
polygon centroid 3×3 mandala grid room scoring recommendations

utility classes dark mode responsive

🚀 Testing & Deployment

🧪
Vitest
Testing framework
Unit & integration testing focused on geometry math and state transitions (Testing Library + jsdom). Playwright handles visual-regression tests; Storybook is used for component development.
unit tests Playwright visual Storybook

tsc + vite build code splitting lazy domains
